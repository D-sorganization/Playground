# GH300 Execution Plan: Search, Filters, and Exercise Aliases

## Summary

Three interconnected features: (1) history search/filter via a new repository method and API endpoint, (2) an alias system that lets short codes like "BP" expand to "Bench Press" in autocomplete without polluting the exercise catalog, and (3) multi-word token matching in autocomplete so queries like "inc db press" match "Incline DB Press".

## Tier

Tier 2 — Core Team (complexity 5, files_affected 5, criteria_count 5)

## Implementation Sequence

The sequence is ordered to satisfy dependencies: schema changes before repository methods, repository methods before routes, routes before integration tests.

### Step 1 — Schema: add `exercise_aliases` table

**File:** `src/workout_tracker/schema.sql`

Append after the existing `sets` indexes:

```sql
CREATE TABLE IF NOT EXISTS exercise_aliases (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    exercise_id INTEGER NOT NULL,
    alias       TEXT    NOT NULL UNIQUE,
    normalized_alias TEXT NOT NULL UNIQUE,
    created_at  TEXT    NOT NULL DEFAULT (datetime('now')),
    FOREIGN KEY (exercise_id) REFERENCES exercises(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_aliases_exercise
    ON exercise_aliases(exercise_id);

CREATE INDEX IF NOT EXISTS idx_aliases_normalized
    ON exercise_aliases(normalized_alias);
```

Design decisions:
- `ON DELETE CASCADE` — removing an exercise removes its aliases automatically; no orphan cleanup needed.
- Both `alias` (display) and `normalized_alias` (lookup) stored; `normalized_alias` uses the existing `normalize_name()` function, matching the pattern used for `exercises.normalized_name`.
- `UNIQUE` on both columns prevents duplicate display aliases and duplicate normalized lookups.

Edge cases:
- Alias text that normalizes to the same value as an existing alias (e.g., "B P" and "BP" both normalize to "bp") — the `UNIQUE` constraint on `normalized_alias` rejects the second insert; the repository must surface this as a clear `ValueError`.
- Alias that normalizes to the same value as an existing exercise's `normalized_name` — this is allowed by the schema (different tables), but the `suggest()` function must handle the case where a query matches both an alias and a real exercise name without double-boosting.

### Step 2 — Models: `ExerciseAlias` dataclass

**File:** `src/workout_tracker/models.py`

Add a new frozen dataclass after `Exercise`:

```python
@dataclass(frozen=True)
class ExerciseAlias:
    alias: str
    exercise_id: int
    id: int | None = None
    normalized_alias: str = ""
    created_at: str | None = None

    def __post_init__(self) -> None:
        if not self.alias or not self.alias.strip():
            raise ValueError("Alias cannot be empty")
        if not self.normalized_alias:
            object.__setattr__(self, "normalized_alias", normalize_name(self.alias))

    def to_dict(self) -> dict[str, Any]:
        return asdict(self)
```

No changes to `Exercise`, `Workout`, or `WorkoutSet` dataclasses are required.

### Step 3 — Repository: alias CRUD + `resolve_alias`

**File:** `src/workout_tracker/db.py`

Add four methods to `WorkoutRepository` in a new `# ---- Aliases` section after the existing Exercises section:

**3a. `add_alias(exercise_id, alias) -> ExerciseAlias`**
- Normalize the alias text with `normalize_name()`.
- INSERT into `exercise_aliases`; catch `sqlite3.IntegrityError` (UNIQUE violation) and re-raise as `ValueError("alias already exists")`.
- Verify the `exercise_id` FK is valid before insert (SELECT exercises WHERE id = ?; raise `KeyError` if missing).
- Return the newly created `ExerciseAlias`.

**3b. `delete_alias(alias_id) -> None`**
- DELETE FROM exercise_aliases WHERE id = ?.
- No error if id missing (idempotent delete is safe).

**3c. `list_aliases(exercise_id=None) -> list[ExerciseAlias]`**
- If `exercise_id` is given: SELECT WHERE exercise_id = ? ORDER BY alias ASC.
- If None: SELECT all ORDER BY exercise_id, alias ASC.
- Map rows via a new `_row_to_alias` static mapper.

**3d. `resolve_alias(query) -> Exercise | None`**
- `norm = normalize_name(query)`
- SELECT e.* FROM exercises e JOIN exercise_aliases a ON a.exercise_id = e.id WHERE a.normalized_alias = ? LIMIT 1
- If a row is found, return `_row_to_exercise(row)`.
- If not found, return `None`.

**3e. `_row_to_alias` static mapper**
```python
@staticmethod
def _row_to_alias(row: sqlite3.Row) -> ExerciseAlias:
    return ExerciseAlias(
        id=row["id"],
        exercise_id=row["exercise_id"],
        alias=row["alias"],
        normalized_alias=row["normalized_alias"],
        created_at=row["created_at"],
    )
```

Edge cases:
- `add_alias` called with an exercise_id that does not exist: raise `KeyError` before attempting INSERT (avoids FK error message leaking raw SQL).
- `resolve_alias` on an empty string: `normalize_name("")` returns `""`, which will not match any stored normalized alias (since `add_alias` rejects empty aliases); return `None` cleanly.
- Concurrent alias insert race: `sqlite3.IntegrityError` caught and re-raised as `ValueError`.

### Step 4 — Repository: `search_workouts` method

**File:** `src/workout_tracker/db.py`

Add `search_workouts` to `WorkoutRepository` in the `# ---- Workouts` section, after `list_workouts`:

```python
def search_workouts(
    self,
    exercise_name: str | None = None,
    date_from: str | None = None,
    date_to: str | None = None,
    min_weight: float | None = None,
    status: str | None = None,
) -> list[Workout]:
```

SQL construction strategy — build a WHERE clause dynamically with a params list:

- Base: `SELECT DISTINCT w.* FROM workouts w`
- If `exercise_name` or `min_weight` is given: JOIN sets s ON s.workout_id = w.id JOIN exercises e ON e.id = s.exercise_id
- `exercise_name`: filter by `e.normalized_name LIKE ?` using `normalize_name(exercise_name)` + `%` suffix (prefix match), OR full substring with `%...%` for broader matching. Chosen behavior: substring match (`'%' + norm + '%'`) to handle queries like "press" matching "Bench Press".
- `date_from`: `AND w.date >= ?`
- `date_to`: `AND w.date <= ?`
- `min_weight`: `AND (s.actual_weight >= ? OR s.planned_weight >= ?)` (matches sets where any weight meets threshold).
- `status`: `AND w.status = ?` — validate against `VALID_STATUSES` before executing; raise `ValueError` on invalid status.
- ORDER BY w.date DESC, w.id DESC.
- Hydrate sets for each returned workout using `_workout_sets(w.id)`.

Edge cases:
- All params None: equivalent to `list_workouts()` but without a LIMIT — caller should add limit param if needed. For safety, add an implicit `LIMIT 200` to prevent unbounded scans on large histories.
- `date_from > date_to`: returns empty result set naturally (no special handling needed; ISO dates sort lexicographically).
- `min_weight = 0`: matches all sets with a non-NULL weight — valid behavior, no special case.
- `min_weight` negative: raise `ValueError("min_weight must be >= 0")`.
- `exercise_name` that normalizes to empty string (all special characters): treat as no filter (skip the exercise_name clause).

### Step 5 — Autocomplete: alias expansion + multi-word token matching

**File:** `src/workout_tracker/autocomplete.py`

Two distinct changes to `suggest()`:

**5a. Alias expansion boost**

Change `suggest()` signature to accept an optional alias resolver:

```python
def suggest(
    query: str,
    catalog: Iterable[Exercise],
    limit: int = 8,
    min_score: float = 50.0,
    alias_resolver: Callable[[str], Exercise | None] | None = None,
) -> list[Exercise]:
```

Before the main scoring loop:
```python
alias_boosted: set[int] = set()
if alias_resolver is not None and q:
    resolved = alias_resolver(q)
    if resolved is not None and resolved.id is not None:
        alias_boosted.add(resolved.id)
```

Inside the scoring loop, after computing `sc = score(q, ex)`:
```python
if ex.id in alias_boosted:
    sc += 6000
```

This ensures the alias-matched exercise floats to the top regardless of other scores. Using a callable (not a direct repo reference) keeps `autocomplete.py` free of database imports (existing design: "Pure functions — no DB").

**5b. Multi-word token matching**

In `suggest()`, after computing `q = normalize_name(query)`, detect multi-word input before the main scoring path. The check uses the original `query` string (before normalization) to detect spaces:

```python
tokens_raw = query.strip().split()
is_multiword = len(tokens_raw) > 1
```

If `is_multiword`:
- Normalize each token: `tokens = [normalize_name(t) for t in tokens_raw if normalize_name(t)]`
- If all tokens are empty after normalization, fall through to normal single-word path.
- Otherwise, run token-match scoring: for each exercise, check whether ALL tokens appear in `exercise.normalized_name` as a substring. Exercises where any token is missing are excluded entirely (score = 0, not added to `scored`).
- Score formula for token-matched exercises: sum of `score(token, exercise)` for each token, then add a `+500` bonus for matching all tokens. This reuses the existing `score()` function per token.
- The alias boost still applies on top of token scoring.
- `min_score` threshold still applies to the final summed score.

Design rationale: token matching via normalized substring (not trigram per-token) is sufficient for the "inc db press" → "Incline DB Press" case. `normalize_name("inc")` = "inc", which is a substring of `normalize_name("Incline DB Press")` = "inclinedbpress". Wait — "inclinedbpress" does contain "inc" as a substring but "db" as a substring as well. Checking: "db" in "inclinedbpress" — yes. "press" in "inclinedbpress" — yes. All three match. Approach confirmed correct.

Edge cases:
- Single-word query with spaces trimmed off: handled by `query.strip().split()` producing one token, so `is_multiword = False`.
- Token that is a stop word or very short (e.g., "a"): will match almost every exercise. No special filtering; the scoring still differentiates by how many tokens match and their individual scores.
- Query with 2+ spaces between words (e.g., "inc  db"): `split()` handles this correctly (splits on any whitespace, ignores empty strings).
- All tokens match but scores sum below `min_score`: exercise excluded, consistent with existing behavior.
- Empty catalog: returns empty list without error.

### Step 6 — API routes: alias endpoints + search endpoint

**File:** `src/workout_tracker/app.py`

Add to `register_routes()`:

**6a. Alias endpoints** (add after existing exercise routes, before workout routes):

```
POST   /api/exercises/<int:ex_id>/aliases
GET    /api/exercises/<int:ex_id>/aliases
DELETE /api/aliases/<int:alias_id>
```

`POST /api/exercises/<int:ex_id>/aliases`:
- Body: `{"alias": "BP"}`
- Validate `alias` is non-empty string.
- Call `repo.add_alias(ex_id, alias)`.
- Catch `KeyError` → 404; catch `ValueError` → 400.
- Return `alias.to_dict()`, status 201.

`GET /api/exercises/<int:ex_id>/aliases`:
- Call `repo.list_aliases(exercise_id=ex_id)`.
- Return `[a.to_dict() for a in aliases]`, status 200.

`DELETE /api/aliases/<int:alias_id>`:
- Call `repo.delete_alias(alias_id)`.
- Return `{"ok": True}`, status 200.

**6b. Workout search endpoint** (add after existing workout list route):

```
GET /api/workouts/search
```

Route must be registered BEFORE `GET /api/workouts/<int:w_id>` to avoid Flask matching "search" as an integer w_id. In Flask, string routes registered before parameter routes take precedence correctly, but explicit ordering in `register_routes` is critical.

Query parameters: `exercise_name`, `date_from`, `date_to`, `min_weight`, `status` (all optional).

```python
@app.get("/api/workouts/search")
def search_workouts() -> Any:
    repo: WorkoutRepository = g.repo
    exercise_name = request.args.get("exercise_name") or None
    date_from = request.args.get("date_from") or None
    date_to = request.args.get("date_to") or None
    min_weight_raw = request.args.get("min_weight")
    status = request.args.get("status") or None
    min_weight: float | None = None
    if min_weight_raw is not None:
        try:
            min_weight = float(min_weight_raw)
        except ValueError:
            abort(400, "min_weight must be a number")
    try:
        workouts = repo.search_workouts(
            exercise_name=exercise_name,
            date_from=date_from,
            date_to=date_to,
            min_weight=min_weight,
            status=status,
        )
    except ValueError as e:
        abort(400, str(e))
    return jsonify([w.to_dict() for w in workouts])
```

**6c. Update `/api/exercises/suggest` route** to pass `alias_resolver`:

```python
@app.get("/api/exercises/suggest")
def suggest_exercises() -> Any:
    repo: WorkoutRepository = g.repo
    q = request.args.get("q", "")
    limit = int(request.args.get("limit", 8))
    catalog = repo.list_exercises()
    results = autocomplete.suggest(
        q, catalog, limit=limit, alias_resolver=repo.resolve_alias
    )
    return jsonify([e.to_dict() for e in results])
```

Edge cases:
- `GET /api/workouts/search` with no params: returns up to 200 most-recent workouts (implicit LIMIT in `search_workouts`). No 400.
- `date_from` or `date_to` in non-ISO format: SQLite date comparison is lexicographic string comparison; malformed dates silently return incorrect results. Add a validation step in the route: attempt `date.fromisoformat(date_from)` and abort(400) on ValueError.
- `status` not in VALID_STATUSES: `search_workouts` raises `ValueError`, route returns 400.
- `DELETE /api/aliases/<alias_id>` for nonexistent id: idempotent, returns `{"ok": True}` (consistent with `delete_workout` and `delete_set` behavior).

## Rollback Boundaries

The implementation has three independent rollback boundaries:

**Boundary A — Schema only (Step 1)**
- Adding `exercise_aliases` table is additive; existing tables/data untouched.
- Rollback: `DROP TABLE IF EXISTS exercise_aliases` — no data loss on other tables.
- Safe to deploy schema change independently before any code changes.

**Boundary B — Alias feature (Steps 1–3, 6a, alias tests)**
- Entirely new table + new methods + new routes. No modifications to existing methods.
- Rollback: revert `db.py` (remove alias methods), revert `app.py` (remove alias routes), drop alias table.
- `suggest()` alias_resolver parameter defaults to `None`; existing callers unaffected on rollback.

**Boundary C — History search (Step 4, 6b, search tests)**
- `search_workouts` is a new method; existing `list_workouts` unchanged.
- New route `/api/workouts/search` does not alter existing `/api/workouts` route.
- Rollback: remove method + route. No schema changes required.

**Boundary D — Multi-word autocomplete (Step 5b, autocomplete tests)**
- Change is entirely within `suggest()` function body; function signature unchanged for existing callers (new param has default `None`).
- Rollback: remove the `is_multiword` branch in `suggest()`; existing tests continue to pass.

## Approach Rationale

- **Alias resolver as callable**: keeps `autocomplete.py` a pure-function module with no database dependency, consistent with its existing design comment ("Pure functions — no DB"). The Flask route passes `repo.resolve_alias` as the callable; tests inject a lambda.
- **Token matching via normalized substring**: avoids adding a new dependency (e.g., trigram per token) and is O(tokens × exercises) with small constants. Correct for the stated use case ("inc db press" → "Incline DB Press").
- **`search_workouts` dynamic WHERE**: follows the same pattern as `update_set`'s dynamic SET clause (already in the codebase). Keeps SQL readable without an ORM.
- **Alias `+6000` boost**: exceeds the existing `+5000` exact-match ceiling, ensuring an alias match always wins even against an exact normalized match on a different exercise. Intentional — aliases are user-declared preferences.

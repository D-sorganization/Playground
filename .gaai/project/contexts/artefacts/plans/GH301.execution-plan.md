# GH301 Execution Plan: Workout Tracker UX Polish

## Summary

Four surface UX features: muscle-group tags on exercises, light/dark theme toggle, undo toasts for destructive actions, and desktop keyboard shortcuts.

## Tier

Tier 2 — Core Team (complexity 4, files_affected ~6, criteria_count 5)

## Implementation Sequence

### Step 1: DB schema — muscle_tags column

**File:** `src/workout_tracker/schema.sql`

- Add `muscle_tags TEXT` column to `exercises` table (nullable, comma-separated free text)
- Migration: use `CREATE TABLE IF NOT EXISTS` pattern with `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` — but SQLite does not support IF NOT EXISTS on ALTER TABLE. Use a helper in `init_db` to detect column existence and add it if missing.

**Edge cases:**
- Tags are free text; no validation of tag values (user-chosen)
- Empty string vs NULL — store NULL when no tags

### Step 2: Model update — Exercise.muscle_tags

**File:** `src/workout_tracker/models.py`

- Add `muscle_tags: str | None = None` field to `Exercise` frozen dataclass

### Step 3: Repository update

**File:** `src/workout_tracker/db.py`

- Update `_row_to_exercise` mapper to include `muscle_tags`
- Update `get_or_create_exercise` INSERT to include `muscle_tags=None`
- Add `update_exercise_tags(exercise_id, tags)` method

### Step 4: API routes — tags endpoint

**File:** `src/workout_tracker/app.py`

- Add `PUT /api/exercises/<int:ex_id>/tags` endpoint accepting `{"tags": "chest,shoulders"}`
- Validate: tags is str or None
- Return updated exercise

### Step 5: Theme toggle — CSS + JS

**File:** `src/workout_tracker/static/style.css`

- Add `:root[data-theme="light"]` overrides for all `--bg*`, `--fg*`, `--border` variables
- Light palette: white/light-grey backgrounds, dark foreground

**File:** `src/workout_tracker/static/app.js`

- On page load: read localStorage `theme` key; apply `document.documentElement.setAttribute('data-theme', ...)`
- If no stored preference: check `window.matchMedia('(prefers-color-scheme: light)')` to set initial theme
- Theme toggle button click: flip theme, persist to localStorage

**File:** `src/workout_tracker/templates/index.html`

- Add theme toggle button to topbar

### Step 6: Undo toasts for destructive actions

**File:** `src/workout_tracker/schema.sql`

- Add `deleted_at TEXT` column to `exercises`, `workouts`, and `sets` tables (nullable)
- Use same migration pattern as Step 1

**File:** `src/workout_tracker/db.py`

- Update `delete_exercise` / `delete_workout` / `delete_set` to be soft-deletes: SET `deleted_at = datetime('now')` instead of hard DELETE
- Update all SELECT queries to filter `WHERE deleted_at IS NULL`
- Restore methods: `restore_exercise(id)`, `restore_workout(id)`, `restore_set(id)` — SET deleted_at = NULL

**File:** `src/workout_tracker/app.py`

- Add restore endpoints: `POST /api/exercises/<id>/restore`, `POST /api/workouts/<id>/restore`, `POST /api/sets/<id>/restore`

**File:** `src/workout_tracker/static/app.js`

- Update `delete` operations to show undo toast (5s window instead of 2.2s)
- During the undo window, if user clicks "Undo": call restore endpoint, refresh UI
- After timeout: toast auto-dismisses (soft-delete stays committed in DB)

### Step 7: Keyboard shortcuts

**File:** `src/workout_tracker/static/app.js`

- Bind `document.addEventListener('keydown', ...)` in `init()`
- `/` → focus `#ex-input` (prevent default `/` browser quickfind)
- `Esc` → blur focused element + close autocomplete
- `n` → start new workout (only when Today tab active and no active workout; or switch to Today)
- `s` → trigger `addSet(true)` (log set), only when Today tab active
- `t` → switch to Today tab
- Guard: skip shortcut when focus is inside an input/textarea/select

## Test Checkpoints

5. Manual QA: theme toggle respects `prefers-color-scheme` on first load

## Risk Register

| Risk | Mitigation |
|------|-----------|
| SQLite `ALTER TABLE` no IF NOT EXISTS | Detect column via `PRAGMA table_info(exercises)` in `init_db`; add only if missing |
| Soft-delete changes break existing DELETE tests | Existing tests that assert delete removes record must be updated to verify soft-delete behavior |
| Undo window race — user hammers undo | Idempotent restore (SET deleted_at = NULL always safe) |
| Keyboard shortcut conflicts with browser | `/` default prevented on keydown; `n`/`s`/`t` guarded by focus check |

## Rollback Boundaries

- Schema migration via `init_db` is additive (nullable columns); no data loss on rollback
- Soft-delete: no hard deletes; all data preserved — safe to revert filtering logic
- Theme: localStorage only, no server state

## Approach Rationale

All features use existing stack (SQLite, vanilla JS, CSS variables). No new libraries. Soft-delete implemented directly in SQLite/Python (consistent with existing repo pattern). Theme uses CSS custom properties (already present in style.css).

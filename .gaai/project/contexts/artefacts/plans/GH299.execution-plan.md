# GH299 Execution Plan

## Tier Assessment
Tier 2 — complexity 7: 5 distinct features, schema migration, new module, 8 new endpoints.

## Approach

### Schema
Add `deleted_at TEXT` column to `exercises`, `workouts`, `sets` via idempotent migration in `_migrate()`. Schema.sql updated for fresh installs.

### New module: `data_mgmt.py`
- CSV parsers for Strong, Hevy, FitNotes (grouped by date+title key)
- Format auto-detection from header row
- JSON export (all non-deleted records)
- JSON import (restore = clear+insert; merge = skip existing by normalized_name)

### `db.py` changes
- `delete_*` methods → soft delete (set `deleted_at = NOW`)
- All list/get methods filter `deleted_at IS NULL`
- New: `restore_workout/exercise/set`, `list_trash`, `purge_trash`
- New: `bulk_rename_exercises`, `bulk_merge_exercises`, `convert_sets_unit`
- New: `_find_exercise_by_normalized` (for import dedup)

### `app.py` new routes
- `GET /api/export`
- `POST /api/import/json` (mode=restore|merge)
- `POST /api/import/csv` (format=strong|hevy|fitnotes or auto-detect)
- `GET /api/trash`
- `POST /api/trash/restore`
- `DELETE /api/trash`
- `POST /api/exercises/bulk` (action=rename_batch|merge|convert_units)

## Test Strategy
TDD: `tests/test_workout_tracker_data_mgmt.py` written before implementation.
Covers all 5 features end-to-end at both repo and HTTP layers.

# GH295 Execution Plan — In-gym ergonomic logging (quick wins)

## Approach

All 7 features are pure ergonomic UI enhancements. No new data models required except:
- One new backend endpoint for last-session recall (reads existing `sets` table)
- Two new repository methods

No schema changes. Tier 2 (complexity ~5-6): multiple frontend features + 1 backend addition.

## Implementation Sequence

### Step 1 — Backend: last-session recall API
- `src/workout_tracker/db.py`: Add `resolve_exercise_by_name()` + `last_session_sets()`
- `src/workout_tracker/app.py`: Add `GET /api/last_session_sets?exercise_name=X&limit=N`
- Checkpoint: route returns correct sets from latest session only

### Step 2 — HTML: new UI containers
- `src/workout_tracker/templates/index.html`: Add timer strip, last-session strip, weight-adj buttons, voice button, plate modal

### Step 3 — CSS: new component styles
- `src/workout_tracker/static/style.css`: Timer strip, plate modal, weight-adj, last-session strip, repeat/voice button styles

### Step 4 — JS: state + timer infrastructure
- `src/workout_tracker/static/app.js`: Extend `state` with timer handles/wake lock; session timer; rest timer (auto-start on execute); wake lock acquire/release

### Step 5 — JS: last-session recall
- `refreshLastSession(exerciseName)` — fetches `/api/last_session_sets`, renders clickable chips; called on `pickSuggestion` and repeat-set click

### Step 6 — JS: repeat last set button
- Add "⟳" button to `renderSetRow`; populates exercise/reps/weight in form

### Step 7 — JS: quick weight ± buttons
- `bindWeightAdj()` — delta buttons adjust weight-input value; called in `init()`

### Step 8 — JS: plate calculator modal
- `calcPlates(target, bar, unit)` — greedy descent over standard plates
- `bindPlateCalc()` — modal open/close/compute; pre-fills from current weight

### Step 9 — JS: voice input
- `bindVoiceInput()` — webkitSpeechRecognition; parses "exercise N by W" pattern; fills form

### Step 10 — Tests
- `tests/test_workout_tracker_gh295.py`: 20 tests covering repo methods, route, and plate calculator logic

## Edge Cases

| AC | Edge case | Handling |
|----|-----------|----------|
| Repeat last set | No exercise selected | Pre-fill only what is known |
| Plate calc | Target < bar weight | Return None → show error |
| Plate calc | Non-standard weight | Return None → show error |
| Last-session recall | Exercise never used | Return empty array → hide strip |
| Voice input | Browser unsupported | Disable button with tooltip |
| Rest timer | Multiple quick executes | Resets on each execute |
| Wake lock | Browser denies | Silent catch, no UX disruption |

## Risk Register

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| `webkitSpeechRecognition` not in all browsers | Medium | Graceful disable when unavailable |
| Wake Lock revoked by OS (battery saver) | Low | Re-acquire on page visibility change |
| Plate calc edge cases (odd weights) | Low | Return None + user-visible error |

## Rollback Boundary

All changes are additive. Removing the `GET /api/last_session_sets` route and reverting the 5 frontend files returns the app to its prior state with no data loss.

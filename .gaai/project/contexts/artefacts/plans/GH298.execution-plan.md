# GH298 Execution Plan — Advanced Stats: Charts, Heatmap, Streaks, Ratios

## Story Summary

Add advanced statistical visualisations and metrics to the Workout Tracker:
- Volume trend sparklines per exercise (weekly / monthly) — SVG
- e1RM progression chart with PR dots — SVG
- Calendar heatmap of training days (GitHub-style) — SVG
- Session metrics: tonnage, avg rest (approx), training density
- Training streak counter (consecutive training days/weeks)
- Strength ratios (user-picked exercise pairs)

## Approach Rationale

**Vanilla SVG** (no chart library) chosen. The project uses zero build tools and vanilla JS. SVG is natively rendered by all browsers, keeps bundle size at zero, and is consistent with the project's philosophy. Data computation stays in `stats.py` (pure functions); the frontend assembles SVG from the returned coordinates.

**Approach evaluation skipped** — this follows the established project convention (pure Python stats functions + vanilla JS frontend). No new dependencies, no architectural change.

## Implementation Sequence

### Step 1 — `stats.py`: New stat functions (TDD first — write tests, then implement)

**1a. `training_streak(sets, today)`**
- Input: iterable of WorkoutSet, optional `today` string (ISO date)
- Computes all distinct training days from executed sets
- Returns `StreakResult(current_streak: int, longest_streak: int, last_training_date: str | None)`
- Edge cases:
  - No sets → current_streak=0, longest_streak=0
  - Streak resets if gap > 1 day
  - `today` parameter used for testing (avoid datetime.utcnow() in prod paths)

**1b. `session_metrics(sets, workout_sets_by_workout)`**
- Input: iterable of WorkoutSet for a single workout (or all)
- Computes per-workout: tonnage (sum actual_weight * actual_reps), set count, exercise count
- Returns `SessionMetrics(workout_id: int, date: str, tonnage: float, sets: int, exercises: int)`
- Duration cannot be derived from schema (no start/end timestamps on workouts) — omit; density = tonnage/set as proxy
- Note: avg rest is not computable from the schema (no rest timestamps) — omit

**1c. `calendar_heatmap_data(sets, weeks=26)`**
- Input: iterable of WorkoutSet, weeks of history
- Returns list of `HeatmapDay(date: str, count: int)` for last N weeks
- count = number of executed sets that day (zero-count days not included)
- Frontend fills the full grid with zeros

**1d. `volume_trend(sets, period="weekly")`**
- Input: executed sets for one exercise, period "weekly"|"monthly"
- Returns list of `TrendPoint(period_label: str, volume: float, sets: int)`
- Weekly: ISO week label (YYYY-WNN), Monthly: YYYY-MM
- Edge cases: empty sets → []

**1e. `strength_ratio(sets_a, sets_b)`**
- Input: two exercise WorkoutSet iterables
- Returns `StrengthRatio(ratio: float | None, e1rm_a: float, e1rm_b: float)`
- ratio = best_e1rm_a / best_e1rm_b if both > 0, else None

### Step 2 — New API endpoints in `app.py`

**2a. `GET /api/stats/advanced`**
- Returns: streak data, heatmap (26 weeks), session metrics for last 30 workouts
- Uses: `list_all_executed_sets()` (existing), new stats functions

**2b. `GET /api/stats/exercise/<int:ex_id>/trend`**
- Query param: `period=weekly|monthly` (default weekly)
- Returns: `{trend: [...], timeseries: [...], personal_records: [...]}`
- Reuses existing `exercise_timeseries`, adds `volume_trend`

**2c. `POST /api/stats/ratio`**
- Body: `{exercise_a_id: int, exercise_b_id: int}`
- Returns: `{ratio: float|null, e1rm_a: float, e1rm_b: float, name_a: str, name_b: str}`

### Step 3 — Frontend: `app.js` additions

**3a. Extend `loadStats()` to call `/api/stats/advanced`**
- Render streak counter (DOM: streak badge with number + "day streak" label)
- Render heatmap SVG (52 columns × 7 rows, cell size 12px, color intensity by count)
- Render session metrics table (last 10 workouts: date, tonnage, sets)

**3b. Exercise drill-down: clicking exercise in per-exercise summary opens detail**
- Fetches `/api/stats/exercise/<id>/trend`
- Renders two inline SVG sparklines: volume trend (weekly) + e1RM progression
- PR dots overlaid on e1RM chart: circles at PR dates

**3c. Strength ratio picker**
- Two `<select>` elements (exercise A, exercise B) populated from exercise catalog
- Computes ratio on select change via POST /api/stats/ratio
- Displays ratio result inline

### Step 4 — `index.html` additions

- Add heatmap container `<div id="stats-heatmap"></div>` in stats section
- Add streak container `<div id="stats-streak"></div>`
- Add session-metrics container `<div id="stats-sessions"></div>`
- Add ratio picker container `<div id="stats-ratio"></div>`

### Step 5 — `style.css` additions

- `.heatmap-cell` — small squares, `--heat-0..4` CSS custom properties for color intensity
- `.sparkline-svg` — inline SVG sizing
- `.streak-badge` — large number + label

## Edge Cases

- Duration/rest: no timestamps on workouts for duration; density computed as tonnage/sets
- Heatmap: weeks boundary truncated to available data — no crash on sparse data
- Strength ratio: exercises with zero e1RM → ratio=None (not div-by-zero)
- Volume trend: exercise with < 2 data points → returns 1-point list (valid)
- Streak: today = a non-training day → current_streak = 0 only if no sets today

## Risk Register

| Risk | Mitigation |
|------|-----------|
| SVG heatmap sizing on mobile | Use viewBox + CSS width:100% |
| e1RM chart with one data point | Render as dot, no line |
| Ratio with exercises not in DB | 404 graceful handling |

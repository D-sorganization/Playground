# GH299 Memory Delta

## Notable Decisions

### Soft delete via `deleted_at` column (not a trash table)
All three tables (`exercises`, `workouts`, `sets`) carry `deleted_at TEXT`. No separate trash table. This keeps queries simple and avoids FK complexity.

### Hard delete on `merge_exercise`
`merge_exercise` uses a hard DELETE (not soft delete) since merging is a catalog management action, not a user deletion. The source exercise ceases to exist in the domain sense.

### `purge_trash` hard-deletes all soft-deleted rows regardless of age
The 30-day window is enforced in `list_trash`, not in purge. Users can always purge early; the system purges all soft-deleted rows when asked.

### CSV import: group by (date, title) key not workout_id
Rows with the same date+title map to the same ImportedWorkout. This handles Strong/Hevy correctly where one workout spans multiple rows.

### JSON import: `_find_exercise_by_normalized` looks up including soft-deleted
During restore the DB is cleared first, so this is moot. During merge, if an exercise was soft-deleted and reimported, it stays soft-deleted (by normalized_name match). This is intentional — users would restore explicitly.

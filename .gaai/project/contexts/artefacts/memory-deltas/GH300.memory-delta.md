## Patterns Worth Preserving

### 1. Alias Resolver as Callable — Keeping Modules DB-Free

The `autocomplete.py` module has no database imports. Instead of coupling it to the DB layer, the `suggest()` function accepts an optional `alias_resolver: Callable[[str], Exercise | None] | None = None` parameter. The caller (`app.py`) passes `alias_resolver=repo.resolve_alias` at the call site.

This pattern preserves module purity (autocomplete logic is purely algorithmic and testable in isolation) while allowing DB-backed behavior at the integration layer. Tests for autocomplete inject a plain dict-lookup lambda rather than a real DB connection.

**Use this pattern** when a pure utility module needs access to data it shouldn't own — pass the lookup as a callable rather than importing the data source.

### 2. Dynamic WHERE Clause with Validated Inputs

`db.py:search_workouts()` builds a SQL WHERE clause by conditionally appending to a `conditions: list[str]` and `params: list` pair. Status values are validated against `VALID_STATUSES` before being interpolated, and dates are validated by the route handler via `date.fromisoformat()`. The SQL line carries `# noqa: S608` to silence the string-interpolation-in-SQL warning where the interpolated values are column/table names (not user input).

**Pattern:** validate all user inputs at the route boundary (400 error), use parameterized queries for values, noqa-annotate only the unavoidable structural interpolations.

### 3. Alias Normalization in `__post_init__`

`ExerciseAlias` is a frozen dataclass. Its `__post_init__` auto-computes `normalized_alias` from `alias` using the shared `normalize_name()` utility. This ensures the normalized field is always consistent with the raw field at construction time, without requiring callers to remember to normalize.

**Pattern:** For dataclasses that carry both raw and normalized/derived fields, compute derived fields in `__post_init__` so the invariant is enforced by the type itself.

### 4. Route Ordering for Literal-vs-Pattern Conflicts

`/api/workouts/search` must be registered before `/api/workouts/<int:w_id>`. Flask's `int` converter already rejects non-integer path segments, so the conflict is actually benign, but registering the literal route first is the correct defensive practice and makes intent explicit. A test (`test_search_route_before_workout_id_route`) was added to guard against accidental reordering.

**Pattern:** Always register literal routes before pattern routes when both could match the same URL structure, and add a regression test that hits the literal route.
